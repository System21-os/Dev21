ARAH PENGEMBANGAN

Mengapa Pindah ke Server Profesional?

Apps Script sudah berjasa sebagai prototipe. Mulai sekarang, seluruh pengembangan difokuskan di server — bukan lagi di Apps Script.

🛑
Dulu: Google Apps Script
  • Terasa lambat — setiap buka laporan harus membaca Google Sheets lewat internet.
  • Dibatasi Google — satu proses maksimal 6 menit; data besar rawan gagal di tengah jalan.
  • Bergantung pihak luar — jika akses Google terganggu, dashboard ikut berhenti.
  • Sulit dikelola tim IT — tidak bisa dipantau, di-backup, atau diatur seperti server biasa.
💎
Sekarang: Server Profesional Mandiri
  • Jauh lebih cepat — data disimpan di database lokal (SQLite) di server sendiri.
  • Tanpa batas kuota — ratusan ribu baris transaksi diproses tanpa batas waktu.
  • Dikendalikan penuh oleh IT — backup terjadwal, pemantauan, dan hak akses di tangan kita.
  • Siap berkembang — fitur baru bisa ditambah dengan alat pengembangan standar industri.
💡
Analogi: Apps Script ibarat warung tenda di lahan orang — cepat dibuka, tapi diatur pemilik lahan. Server profesional ibarat ruko milik sendiri — buka 24 jam, kokoh, dan kita yang pegang kuncinya.
PRODUCT REQUIREMENTS DOCUMENT

PRD: Apa, Untuk Siapa, dan Seberapa Berhasil

Ringkasan kebutuhan produk sebagai pegangan pengembangan selanjutnya.

1. Masalah
Manajemen sulit memantau capaian penjualan F&B ratusan outlet secara cepat karena laporan tersebar di banyak file Excel dan harus direkap manual.
2. Pengguna
  • ADMIN / Head Office — melihat nasional + mengelola data & user.
  • RM (Regional Manager) — memantau region & area di bawahnya.
  • AREA — memantau outlet di areanya.
3. Ukuran Keberhasilan
  • Angka KPI 100% sama dengan rumus resmi.
  • Dashboard terbuka dalam hitungan detik.
  • Data aman: backup harian & jejak audit.
4. Kamus KPI (bahasa sederhana)
SPH
Rata-rata belanja F&B per penonton.
Omzet F&B ÷ Penonton
DS%
Berapa persen penonton yang belanja.
Bill ÷ Penonton
AT
Rata-rata nilai satu struk belanja.
Omzet F&B ÷ Bill
Achv%
Pencapaian terhadap target SPH.
SPH ÷ Target
+/− Rp
Selisih rupiah dari target.
(SPH − Target) × Penonton

Kenapa "jumlahkan dulu, baru bagi"?
SPH sebuah region = total omzet ÷ total penonton region itu, bukan rata-rata SPH tiap outlet. Dengan begitu outlet kecil tidak membuat angka region melenceng.
Growth yang adil (apple-to-apple)
Melihat 1–15 Oktober (15 hari)? Sistem otomatis membandingkannya dengan 15 hari tepat sebelumnya, yaitu 16–30 September.

Dashboard Overview & Alat Bantu di Setiap Halaman

Halaman pertama setelah login: ringkasan kinerja dalam satu layar, plus filter dan tombol yang selalu tersedia.

TUR APLIKASI · 3/4

Halaman Analitik: Bandingkan, Petakan, Telusuri

Halaman untuk menggali "kenapa" di balik angka.

📈
Comparison Detail
Membandingkan kinerja tahun ini vs tahun pembanding, dikelompokkan per bulan, kuartal, atau semester.
  • Metrik: SPH, GBO (porsi F&B terhadap omzet bioskop), DS%, AT, Penonton, Bill, HTM.
  • Bagian: Pergerakan per periode, Pivot periode, Performa per RM/Area/Outlet, Ranking Outlet, Ringkasan & catatan metode.
  • Export CSV dan PDF.
🗺️
Mapping Nasional
Peta Indonesia (38 provinsi, 514 kota/kabupaten) yang menampilkan kinerja per wilayah/kota.
  • Pilih tampilan Jumlah Penonton atau SPH, lengkap dengan growth vs periode sebelumnya.
  • Peringkat Wilayah, Distribusi per Wilayah, rincian LOB × Outlet, dan kolom cari wilayah.
  • Peta Gelap / Terang; berjalan tanpa internet. Kota yang namanya tak cocok tetap dihitung dan diberi peringatan.
🏢
Nasional / RM / Area / Outlet Perf.
Tabel laporan per Periode × Entitas berisi SPH, Target, DS%, AT, Admisi, +/− Rp, dan Achv — pilih Daily, Weekly, Monthly, atau Quartal.
🏪
Outlet Summary Performance
Ringkasan tiap outlet yang bisa dibuka per bulan. Menampilkan Sum Achv (jumlah bulan capai target) dan Sum Not Achv. Bulan tanpa target ditandai "—", tidak dihitung gagal. Ada Expand All dan export Excel.
TUR APLIKASI · 4/4

Halaman Laporan & Administrasi

Tempat data dikelola. Semua tindakan berisiko diberi pengaman berlapis.

▤
Report Detail SEMUA
  • Tabel transaksi baris per baris dengan pencarian kode / outlet / area / RM.
  • Export Excel untuk semua role.
  • ADMIN: Edit baris & Hapus Terpilih. Baris yang dihapus disalin dulu ke log, jadi tetap bisa ditelusuri.
⚙️
Master Data ADMIN
  • Daftar outlet: kode, nama, Area, RM, AM, Kota, LOB, Class, target.
  • Tambah, ubah, nonaktifkan, dan pulihkan outlet.
  • Menjadi acuan pencocokan setiap kali data diunggah.
☁️
Upload Data ADMIN
  • Tarik & lepas file CSV, XLS, XLSX, XLSM.
  • Atur baris judul & pilih kolom yang diimpor.
  • Jika data sudah ada: Timpa, Lewati, atau Tambah baru.
  • Outlet yang tidak dikenal masuk log unmatched untuk dibereskan.
🗑️
Delete Data ADMIN
  • Hapus per rentang tanggal atau per bulan.
  • Alur 3 langkah: Pratinjau → Konfirmasi token → Eksekusi, sehingga tidak ada salah hapus karena salah klik.
👥
Master User ADMIN
  • Tambah / ubah user: username, nama, sandi, role (ADMIN, RM, AREA), status.
  • Aktif / Nonaktif tanpa menghapus akun, dan Reset Sandi.
  • Username RM/AREA = nama region/area yang boleh dilihat (mis. "JAKARTA 1").
🔑
Akun & Log SEMUA
  • Ganti Sandi sendiri (sandi lama + sandi baru 2×).
  • Sesi login bertahan 7 hari, lalu harus login ulang.
  • ADMIN dapat membuka Log Akses: siapa, kapan, dari mana.

WORKFLOW MIGRASI

Dari Laptop Sampai Online di Domain Kantor

Lima langkah. Tim IT cukup menyiapkan server dan domain — sisanya sudah disiapkan di dalam folder proyek.

1 · LAPTOP

Rapikan & Kemas

Hapus kunci AI lama dari kode, buat backup terakhir (npm run backup), kirim folder lewat Git/ZIP. File .env dikirim terpisah secara aman.

Hasil: folder + app.db
→
2 · SERVER

Siapkan Server

Server Linux/Windows di jaringan kantor dengan Docker atau Node.js 22.13+.

Disiapkan tim IT
→
3 · ATUR

Isi Pengaturan

Taruh folder & app.db, isi .env: HOST=0.0.0.0, ALLOWED_HOSTS=domain, AUTH_PEPPER, kunci AI baru.

± 10 menit
→
4 · NYALAKAN

Jalan 24 Jam

docker compose up -d — atau PM2. Otomatis hidup lagi bila server restart.

Cek: npm test lulus
→
5 · ONLINE

Domain + HTTPS

Pasang Nginx dari template, sambungkan domain (mis. kpi.perusahaan.co.id) dan sertifikat SSL.

Live 🎉
✅ Sudah tersedia di folder
Dockerfile, docker-compose.yml, nginx-production.conf, panduan migrasi, alat backup/restore, dan uji otomatis.
🧑‍💻 Yang dikerjakan tim IT
Menyediakan server, domain/DNS, sertifikat SSL, firewall, dan jadwal backup harian ke storage kantor.
⚠️ Wajib diingat
AUTH_PEPPER harus sama dengan yang lama. Jika hilang, semua user tidak bisa login dan sandi harus di-reset.
KEAMANAN

Seberapa Aman Aplikasi Ini?

Penjelasan jujur: apa yang sudah kuat, dan satu hal yang wajib dibereskan sebelum serah-terima.

🛡️
Yang sudah kuat
  • Sandi diacak (PBKDF2 + salt + pepper) — bahkan admin database tidak bisa membaca sandi asli.
  • Daftar izin fungsi — browser hanya boleh memanggil fungsi yang sudah disetujui.
  • Penjaga domain — permintaan dari situs atau alamat asing ditolak.
  • Cek jabatan di server — fitur ADMIN tetap terkunci walau tampilan diakali.
  • Jejak audit — login dan penghapusan data tercatat.
🔍
Temuan: 1 kunci AI tertulis di kode
File Code.gs baris 609–612 (fungsi setApiKeyOnce) masih berisi kunci Anthropic dari masa uji coba.
🧯
Perbaikan (± 15 menit):
1. Nonaktifkan kunci lama di konsol Anthropic.
2. Hapus fungsi tersebut dari kode.
3. Isi kunci baru hanya di file .env server — server sudah otomatis membacanya dari sana.
